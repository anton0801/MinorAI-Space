# Спецификация следующего этапа

Это требования к реализации, не описание уже работающего результата. Последнее решение пользователя — в START_HERE.md. Суммы, тарифы, paywall B и общий доступ не менять.

## 1. Библиотека вместо двух разных списков

В текущем ViewController есть sidebar с Maps/Slides/Chats, а Views/Home/LibraryView содержит отдельную библиотеку Maps/Slides. Не создавать третью. Общие данные, сортировка, поиск, закрепления, контекстные действия и состояние должны принадлежать одному библиотечному модулю.

### Навигация и состав

- Главная остаётся прежней: помощник, продолжение проекта, ввод, голос, нижнее «Меню». Верхний hamburger заменить понятным символом библиотеки (`books.vertical` либо `rectangle.stack`), accessibility label «Библиотека». Не менять реальный логотип и анимацию сплеша.
- Верхняя кнопка открывает библиотеку непосредственно; «Меню → Библиотека» открывает тот же экран. Не открывать последовательно меню и ещё одну панель поверх него.
- При входе с главной возврат «Помощник»; при входе из меню — «Меню». После открытия документа и возврата восстановить вкладку, запрос и позицию списка. Закрытие не очищает чат/черновик помощника.
- Постоянный заголовок «Библиотека», три вкладки «Карты / Слайды / Чаты». Чаты — существующая история помощника. Чат внутри карты остаётся в проекте; не дублировать его отдельной беседой без существующей модели такого поведения.
- Поиск внутри выбранной вкладки; placeholder уточняется: «Поиск карт», «Поиск презентаций», «Поиск чатов». На концепте показан общий placeholder; при реализации предпочесть уточнённый.
- Секции «Закреплённые» и «Недавние». Закреплённый объект не дублируется в недавних. Сортировка: недавно открытые, изменённые, по имени. Сохранить существующие возможности списков, включая доступ к выполняющейся генерации.
- Плюс в шапке создаёт сущность выбранной вкладки: карту, презентацию или новый чат. Явная accessibility-подпись. Новая беседа не удаляет предыдущую историю.
- Строка: миниатюра/тип, название до двух строк, дата и уместные метаданные; меню «…» с существующими переименованием, закреплением, дублированием, удалением/выходом по правам. Для общего доступа использовать уже переданный модуль, не переписывать роли.
- «Сегодня» остаётся в нижнем меню; если старый прямой вход убирается из библиотеки, он должен оставаться доступным там. Не удалять функцию.
- Компактный лимит — из AccountStore, только когда применим; не фиксировать «3» из макета в коде. «0 из 3» означает использовано, индикатор пустой. Нажатие ведёт к уже существующему экрану лимитов/подписки. «Настройки» — подписанная строка со стандартной шестерёнкой, не огромный отдельный знак.
- Убрать жёсткий верхний отступ 80 pt старой панели; использовать safe area и системную высоту шапки. Нижний блок не перекрывает строки и клавиатуру; при крупном тексте включается в scroll-контент.

### Движение

Прямой вход с главной: горизонтальный переход 280–320 мс, ease-out, без пружинного удара. Список появляется единым блоком с opacity и сдвигом не больше 8 pt; допустима задержка первых 3 строк по 20 мс, суммарно до 60 мс. Не анимировать заново при возврате из документа. Из меню — обычный push. Не запускать одновременно горизонтальный переход и открытие нижнего меню. Сохранить интерактивный возврат, но не перехватывать жесты карты/слайдов. Reduce Motion: короткий crossfade без движения. Фокус VoiceOver переносится на заголовок и возвращается к открывшей кнопке.

Состояния: пустая вкладка с одним соответствующим действием; поиск без результатов; загрузка; ошибка чтения с повтором; генерация; удалённый/недоступный документ; длинные имена и список 100+ объектов. Не заполнять пустой список выдуманными проектами.

## 2. Источники: оригинал, фрагмент, происхождение

Сейчас ProjectMaterial хранит text/url/pages, а passage(mentioning:) ищет совпадение текста. Это не доказательство точной привязки. NodeOrigin.material указывает происхождение, не подтверждение каждого утверждения узла. Старым материалам нельзя автоматически присвоить страницу или время.

### Пользовательский путь

Узел → «Источники» → список материалов и отдельные «Идеи ИИ». Узлы не обрастут сносками. У источника показываются имя, тип, проверенный локатор и краткая выдержка. Один узел может иметь несколько ссылок. При отсутствии точного соответствия: «Материал связан с узлом. Точный фрагмент не указан».

- PDF: «Открыть страницу» открывает сохранённый оригинал на нужной странице. Подсветка только при наличии точных координат/диапазона; страница без координат открывается без выдуманной подсветки. Номер в UI начинается с 1; внутренний индекс может начинаться с 0 и преобразуется явно. Если у PDF есть печатные номера, отдельно обозначить индекс файла.
- Голос: «Слушать фрагмент» открывает сохранённое аудио на startTime. Нажатие строки расшифровки перемещает воспроизведение. Выделение следует за фактической позицией. Выход останавливает воспроизведение; возврат к узлу восстанавливает его выбор и масштаб карты. Допустимый допуск seek проверяется на реальном формате записи; нет ложной точности до миллисекунд.
- YouTube: хранить исходную ссылку и сегменты доступной расшифровки. Открывать официальный URL с временем, если оно подтверждено сегментом; иначе просто видео с честной подписью. Не обещать локальный оригинал видео, офлайн-плеер или скачивание ролика.
- Скан/фото: хранить исходное изображение, позицию страницы и проверенные OCR-координаты, если они есть. Ошибка OCR не превращается в уверенную цитату.
- Ссылка/текст: сохранённый извлечённый фрагмент и URL, дата извлечения. Открытие живого сайта не гарантирует тот же текст. TXT/RTF не получают придуманные PDF-страницы.
- «Идея ИИ» остаётся явной пометкой; связь с материалом сама по себе не делает утверждение подтверждённым. Факт совпадения цитаты и смысловая достоверность — разные вещи.

### Контракт данных и импорт

Сохранить совместимость ProjectMaterial/NodeOrigin. Добавить версионируемые сущности: OriginalAsset (ID, относительный путь, MIME, размер, hash, состояние); SourceSegment (стабильный ID, materialID, версия оригинала/извлечения, текст, page/time/range/rect по типу); Citation (ID, nodeID/claimID, segmentIDs, excerpt, статус привязки). Не хранить абсолютный путь пользователя. Не сопоставлять по одному названию.

Копировать файл из document picker в управляемое приватное хранилище приложения, пока действителен security-scoped доступ. Импорт: проверка размера/типа → временная копия → завершение записи и hash → извлечение → проверка ссылок → публикация материала. При сбое не показывать «Оригинал сохранён». Ограничения размера/страниц брать из действующего продукта; textLimit и тарифный лимит страниц — разные ограничения.

Для будущих голосовых материалов нужно сохранять сами аудиобуферы и время сегментов распознавания; текущей formattedString недостаточно. Системная диктовка без записи остаётся текстом без плеера. Согласие/индикатор записи и прерывание звонком должны сохранять понятное состояние. Не выдавать старому тексту синтетические таймкоды.

Привязки модель возвращает через разрешённые segmentID. Проверять принадлежность материалу, границы времени/страницы, существование оригинала; цитату брать из сохранённого сегмента. Невалидная ссылка становится непроверенной, не скрыто исправляется приблизительным поиском.

Старый материал: «Сохранён только текст» + «Прикрепить оригинал». Повторное прикрепление проверяет hash/содержимое; другой файл — новая версия, старые ссылки отмечаются требующими проверки. Не подставлять автоматически локаторы новой версии в прежние цитаты.

### Состояния и границы

| Ситуация | Поведение |
|---|---|
| Нет места / запись не завершилась | Ошибка и повтор; текст не теряется; нет успешного статуса оригинала |
| PDF защищён / повреждён / без текста | Понятное сообщение, возможность выбрать другой; доступное OCR отдельно, без обещания результата |
| Файл утрачен, цитата есть | Показать сохранённую выдержку; «Оригинал недоступен»; повторное прикрепление |
| Устаревшая привязка | «Фрагмент требует проверки»; открыть материал без точного jump |
| Нет сети | Локальные оригиналы доступны; YouTube/сайт — сообщение и ссылка для повтора |
| Удаление оригинала | Объяснить потерю просмотра; удаление файла не удаляет узлы; цитаты помечаются недоступными |
| Общая карта | Оригиналы остаются приватными. Не передавать файл, полный текст, приватную выдержку или локальный путь участникам автоматически |

Если origin уже синхронизируется, отдельно проверить payload: участнику допустимо сообщить «Материал недоступен», но не утечь содержимым. Не менять общий доступ ради источников. Файлы и текст не писать в телеметрию. Локальное удержание файлов после закрытия/перезапуска входит в сценарий; cloud backup и перенос на другой iPhone — отдельный отложенный этап.

## 3. Схемы как редактируемые данные

Текущих center и nodes:[String] в SlideDiagram недостаточно. Добавить совместимую версию модели с ID узлов, ID рёбер, from/to, порядком, подписями/стилем и параметрами раскладки. Для матрицы отдельные оси, подписи, значения/ячейки; не изображать координатную модель произвольным графом. Старые diagram продолжают открываться и сохраняться без потери данных.

| Вид | Поведение |
|---|---|
| Процесс | Упорядоченные шаги и направленные связи. Вставить после выбранного шага разделяет его последовательную связь на две. Дополнительные связи добавляются явно |
| Цикл | Последний шаг замыкается в первый; вставка сохраняет кольцо. 0/1 шаг — явное пустое/начальное состояние, без бессмысленных стрелок |
| Иерархия | Один родитель, несколько детей; перенос ветки меняет родителя; запрещены самоссылка и цикл. Удаление предлагает удалить ветку или поднять детей |
| Матрица | Варианты «2×2» с подписанными квадрантами и «По осям» с числовыми координатами. Перемещение обновляет данные; смена типа требует понятного преобразования, не потери значений |

Панель: «Шаги / Связи / Стиль» у графов; «Элементы / Оси / Стиль» у матрицы. Нажатие узла выбирает его и открывает редактирование; стрелки выделяются отдельно. У связей — начало/конец, направление, подпись, удаление. Проверять отсутствующие вершины, дубли и самоссылки. Пользователь не обязан рисовать стрелку пальцем: есть выбор двух шагов списком.

Автораскладка пересчитывает координаты и маршруты после изменения состава, порядка или размера текста. Связи заканчиваются на границах фигур, не в тексте. Перемещение узла обновляет концы связи. Ручной режим хранит координаты; «Расположить автоматически» — явное отменяемое действие. Перетаскивание не должно незаметно менять смысл последовательности; перестановка шагов — отдельная команда с обновлением связей.

При удалении узла показать последствия для связей. Автосоединять соседей можно в простом последовательном процессе/цикле; произвольные дополнительные связи не создавать по догадке. Преобразование между видами показывает preview; неподдерживаемые связи/координаты не отбрасываются молча.

Добавление, удаление, переименование, связь, перенос и стиль — полноценные Undo/Redo-команды. Одно перетаскивание — одна команда; один AI-запрос — одна транзакция после preview. Undo возвращает ID, связи, расположение и выбор. Отмена sheet не равна Undo уже применённых правок: поля формы имеют явные «Готово/Отменить», прямые действия на холсте отменяются общей командой.

Длинный текст: перенос и размер блока, затем перестройка; не уменьшать шрифт до нечитаемого. Большой граф: увеличить холст редактора; перед экспортом проверять влезание на слайд и предлагать разделение/другую раскладку. Нельзя просто обрезать крайние узлы. На телефоне дать развернуть холст и редактировать шаги списком с клавиатурой.

### Экспорт

Единая вычисленная геометрия питает экран, PDF и PPTX. PDF сохраняет векторные фигуры/текст/линии, насколько поддерживается текущим экспортёром. PPTX должен содержать редактируемые фигуры и текст, а для связей — настоящие коннекторы с привязкой к фигурам, если заявлено продолжение редактирования в PowerPoint. Растровый fallback должен быть явно обозначен; он не проходит критерий редактируемой схемы. Обязательна проверка в PowerPoint либо совместимом просмотрщике и отдельно структуры PPTX; успешное создание ZIP-файла не подтверждает качество слайда.

## 4. Обновление из карты без потери ручных правок

Сейчас updateFromMap генерирует новый набор, replaceWithUpdate проверяет slides==base и заменяет массив, есть копия и Undo. Это полезные защиты, но не merge. Сохранить их смысл; не объявлять целую перегенерацию точечным обновлением.

### Данные для сопоставления

Нужны стабильные sourceNodeID → slideID → field/elementID, версия карты, последний применённый исходный снимок и последний сгенерированный базовый текст каждого связанного поля. Для bullets тоже стабильные ID, не индекс массива. Связь может быть много-к-многим. Переименование/перестановка узла не создают новый объект. Несвязанные с картой пользовательские слайды сохраняются.

Сравнивать три состояния: **база** последнего согласованного обновления, **текущее** содержимое пользователя и **предложение** по новой карте. Новый AI-текст сам по себе не означает изменение карты: генерировать и предлагать изменения только для затронутых source IDs. Стиль и структура хранятся отдельно от связанного содержимого.

| Сравнение поля | Действие |
|---|---|
| Карта изменилась, пользователь поле не менял | Предложить обновление, отмеченное по умолчанию; применить только после review |
| Пользователь менял, карта не менялась | Сохранить текущее поле, не предлагать переписать |
| Обе стороны изменили одно поле по-разному | Конфликт: мой текст / из карты / ручное редактирование. По умолчанию оставить мой |
| Обе стороны пришли к одному значению | Без конфликта и лишней операции |
| Новая ветка | Предложить пункт/слайд с местом вставки; не менять остальной порядок |
| Ветка удалена | Предложить удалить связанное содержимое или оставить самостоятельным. При ручных правках не удалять автоматически |

Всегда сохранять ручные заметки, оформление, картинки, свободные элементы, hidden, переходы и порядок незатронутых слайдов. Если новый текст не влезает, отметить переполнение и дать исправить/разделить; не сбрасывать тему и не растягивать всё молча. Изменения состава схем проходят через её модель и связи.

### Review и применение

1. «Обновить из карты» фиксирует ревизии карты и всей презентации, включая style/notes/elements; идёт подготовка с отменой. Исходная презентация не изменяется.
2. Список по слайдам: изменённые поля, additions/deletions, конфликтные места. Галочки выбирают независимые изменения; зависимые операции группируются. «До / После» показывает именно выбранный набор.
3. Конфликт: радио «Оставить мой текст» / «Взять из карты», действие «Отредактировать вручную». Можно осознанно сохранить своё. CTA показывает число фактически изменяемых объектов, а не число рассмотренных конфликтов. На генеративном макете счётчик условный; вычислять его из delta.
4. Перед применением ещё раз проверить ревизии карты и всей презентации. При изменении — «Документ изменился. Обновите сравнение». Нельзя накладывать устаревший preview. По возможности сохранить решения только для неизменившихся conflict IDs; остальные показать заново.
5. Применить атомарно как один Undo-шаг. Успех только после подтверждённой локальной записи; ошибка оставляет текущую презентацию и выбранный preview для повтора. Undo восстанавливает также lineage, base и sourceRevision; Redo — весь результат.
6. Существующая «Сохранить как копию» может остаться запасным действием. Она не заменяет merge и не возвращает отложенный переключатель версий.

При частичном принятии нельзя просто пометить всю карту обработанной одним sourceRevision: обновлять базу/статус по принятым полям. Для «оставить мой текст» сохранить ручное переопределение и ревизию рассмотренного предложения, чтобы не спрашивать то же самое повторно. При следующем реальном изменении источника конфликт снова рассматривается. Пропущенные изменения остаются доступными к рассмотрению; повторный запуск не дублирует уже добавленные пункты.

Старые презентации без lineage: явное «Для этой презентации ещё нет точной связи с узлами». Разрешить ручное сопоставление с подтверждением или текущий безопасный сценарий копии. Не делать тихий merge по совпадению названий/порядка. Удалённая исходная карта не блокирует открытие и редактирование презентации; обновление из неё недоступно с объяснением.

## 5. Приёмка и порядок реализации

Сначала сверить текущие исходники и чужие изменения. Порядок: единая библиотека → оригиналы/сегменты → модель и геометрия схем → lineage и merge → интеграционные проверки. Не связывать доступность первых этапов с отложенным cloud sync.

| Проверка | Ожидаемый результат |
|---|---|
| Оба входа в библиотеку; переключение 3 вкладок; открытие и возврат | Одна история, одинаковые операции; правильный back; сохранены запрос, scroll и черновик помощника |
