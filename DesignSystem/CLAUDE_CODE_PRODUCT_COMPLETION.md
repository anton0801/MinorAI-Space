# Задание Claude Code: завершить UX карт/презентаций и заменить нижний вход на «Меню»

> Актуализация 12 октября 2026 после последнего решения пользователя: автоматическое открытие сохранённой презентации из карты, переключатель нескольких презентаций и «Создать ещё» **отложены**. Не реализовывать этот сценарий сейчас. Сохраняется текущий явный вход в создание презентации из карты; готовые документы доступны через библиотеку. ## Цель и обязательный контекст

Дополнительная проработка после первого пакета: `concepts/2026-10-12/paywall-collaboration-diagrams/README.md` — два варианта paywall, роли/приглашения/участники, новый слайд и редактируемые схемы. Новые поля и исправления уже могли появиться в коде после аудита, поэтому сначала проверить фактическое состояние.

Реализовать выбранное направление Minor AI: эффектный существующий сплеш открывает помощника. Помощник остаётся главной страницей. Карты, презентации, задачи и шаблоны доступны из нового меню. Сохранить текущие данные и возможности; устранить разрыв между концептами и поведением приложения.

- `assistant-flow`: карта из чата, AI-предложения, экспорт, голос.

Источники должны открываться отдельной панелью из меню карты/узла, без постоянных номеров цитат и бейджей на узлах; материалы и идеи ИИ разделены внутри панели. Эти новые экраны — концепты, не подтверждение существующей функциональности.

Focus — основное оформление редакторов. Space-dashboard не заменяет главную. Paper не включать как системную светлую тему без отдельного решения. У документов могут быть свои светлые темы. Реальный логотип использовать из Assets, не вырезать из генеративных картинок.

Это спецификация поведения, не требование воспроизвести генеративные изображения пиксель в пиксель. При конфликте с динамическим текстом, клавиатурой и сохранением данных приоритет у работоспособности и понятного UX.

## 1. Нижняя кнопка главной

Заменить иконку карты и подпись «Карты» на одну компактную горизонтальную кнопку `иконка сетки 2×2 + Меню`. EN: `Menu`. SF Symbol семейства square.grid.2x2, либо согласованный существующий символ с четырьмя скруглёнными плитками. Значок 19–21pt; надпись 14–15pt medium; высота зоны нажатия минимум 44pt; визуальная капсула примерно 112–128×44pt, адаптивная ширина для локализации. Поверхность едва светлее фона, обводка слабая. Это вторичное действие, не огромная белая CTA и не плавающая центральная tab bar.

Разместить под композером с зазором около 12pt, над нижней safe area. Не использовать фиксированный сдвиг на 30pt и высоту UIScreen как основу раскладки. Учитывать размер контейнера, SE, большой шрифт, клавиатуру. При открытой клавиатуре кнопка может скрываться вместе с нижним декоративным пространством; доступ к меню остаётся через навигацию. Тап: scale 0.97 на 90–110ms, один лёгкий haptic при принятом открытии, если это разрешено настройками устройства.

Верхнюю левую кнопку оставить входом в историю разговоров и материалов; accessibility label «История». Нижняя кнопка открывает меню возможностей. Не делать два одинаковых меню с разными маршрутами. Текущий sidebar с картами/слайдами/чатами можно сохранить как быстрый доступ, используя общий router и единые записи хранилищ.

## 2. Что открывается

Вторичный полноэкранный экран, визуально выезжающий снизу. Это не половинный sheet со вложенным длинным каталогом.

Содержание сверху вниз:

1. Заголовок «Меню» / `Menu`; справа закрытие с доступным названием «Вернуться к помощнику».
2. Четыре компактных действия в сетке 2×2: «Новая карта» / `New map`, «Презентация» / `Presentation`, «Сегодня» / `Today`, «Мои материалы» / `My materials`. Короткие подписи: «Из темы или материала», «Из карты или с нуля», «Задачи и напоминания», «Карты и слайды». Одна строка заголовка или естественный перенос, без уменьшения шрифта до микротекста.
3. Строка «Шаблоны» / `Templates` с превью структур, открывает существующие шаблоны карт/презентаций в общей оболочке.
4. «Продолжить» / `Continue`: максимум две реальные недавно открытые записи с миниатюрой и типом. При отсутствии документов секцию убрать, не показывать выдуманные примеры. Активная генерация показывается отдельной строкой с возможностью вернуться к ней.
5. Внизу спокойная строка «Настройки»; при необходимости вход в поддержку через настройки. Не помещать здесь второй paywall-блок.

Меню не содержит сетку PDF/YouTube/голос: это содержимое следующего экрана «Новая карта». Не переносить туда большой символ помощника, графики использования или рекламные карточки.

При выборе назначения меню переходит в дочерний экран. Возврат из дочернего экрана возвращает меню с прежней прокруткой; закрытие меню возвращает помощника. Если редактор открыт по результату чата или deep link, «Назад» возвращает в фактический источник, а не всегда в меню. Чат, черновик, вложения, выбор модели и выполняющийся запрос не сбрасывать ради навигации. Не вызывать endSession() для простого открытия/закрытия меню.

## 3. Анимация: сохранить характер, убрать чрезмерное сжатие

Исходная точка: `ViewController.swift`, кнопка Image("mind"), isMindActive; помощник уходит вверх с scale 0.05–0.1, CreateMapView появляется снизу, spring response 0.6/damping 0.7. Меняем назначение на меню и согласуем движение одной управляющей фазой.

Предлагаемые значения — стартовые для проверки на устройстве, не обещание точной длительности физической пружины:

| Слой | Начальное состояние | Конечное состояние | Время от принятого тапа |
|---|---|---|---|
| Помощник | scale 1, y 0, opacity 1 | scale 0.97, y −16pt, opacity 0 | 0–180ms |
| Фон меню | y = высота контейнера, opacity 1 | y 0, opacity 1 | 0–300ms, быстрый старт и плавное торможение |
| Слабый mint-акцент у верхнего края меню | opacity 0 | кратко 0.06 → 0 | 40–300ms; не непрерывное свечение |
| Заголовок и закрытие | opacity 0, локальный y 8pt | opacity 1, y 0 | 70–190ms |
| Сетка четырёх действий как одна группа | opacity 0, y 12pt | opacity 1, y 0 | 100–240ms |
| Шаблоны | opacity 0, y 10pt | opacity 1, y 0 | 135–275ms |
| Продолжить и настройки как группа | opacity 0, y 10pt | opacity 1, y 0 | 170–300ms |

Не анимировать четыре плитки и каждый подпункт длинной очередью. Общая композиция завершает появление примерно за 300ms. Не делать масштаб 0→1, вращения всего экрана, вспышки, новый сплеш или пролёт логотипа при каждом нажатии.

Переход должен немедленно реагировать на тап и поддерживать обратное движение. Основной экран меню двигается согласованной анимацией; появление групп не запускает сетевые операции. Вычисление и рендер миниатюр не блокируют первый кадр. Подготовить лёгкие placeholders, реальные миниатюры подставлять без сдвига геометрии.

Закрытие: 220–240ms, меню уходит вниз, помощник возвращается к scale 1/y 0/opacity 1. Контент меню остаётся цельным, без обратного каскада по строкам. Прерывание закрытия/открытия продолжает движение от текущей позиции, а не пересоздаёт экран с начала.

Появление групп декоративное: видимые кнопки доступны до окончания всей последовательности; невидимые элементы не перехватывают касания. После выбора маршрута не допускаются повторные переходы от двойного тапа. Не ставить глобальную блокировку взаимодействий по таймеру на 600ms.

Reduce Motion: вместо движения/масштабирования/каскада — единый crossfade 120–150ms; акцентную волну убрать. При открытии с аппаратной клавиатуры — сразу стабильное состояние, без декоративной очереди. VoiceOver переносит фокус на заголовок меню; закрытие возвращает на кнопку меню. Помощник под меню недоступен для accessibility и касаний.

Опциональный жест закрытия: вниз из верхней области, не перехватывать вертикальную прокрутку карточек. Порог ~80pt либо выраженный быстрый свайп вниз; учитывать высоту экрана, отменённый жест и второй палец. При отсутствии уверенной реализации достаточно доступной кнопки закрытия — жест не блокирует выпуск.

Входные фазы запускать только при реальном открытии меню. Синхронизация, обновление recent, возвращение из дочернего редактора и смена темы не должны повторно прятать все блоки. После background/foreground — восстановить устойчивое состояние.

## 4. Навигация и архитектурные ограничения

Сначала проверить существующий TopLayer, auth gate, onboarding, paywall, sidebar, клавиатуру и deep links. Ввести единый источник маршрута (root assistant/menu + дочернее назначение) вместо добавления ещё одного несвязанного Bool поверх isMindActive/openMapID/openDeckID. Конкретные типы выбрать после чтения проекта; не требуется переписывать всё приложение за один шаг.

Разделить UI маршрута и состояние документов/запросов. Объект редактора не должен терять выделение, zoom, текущий слайд или Undo при каждом переключении вкладки. Загружать документы по устойчивым ID из Store, не держать единственную устаревшую копию перед сетевым ответом. Сохранить совместимость `-mindMode`, demo-флагов, widget links, minorai://today, map/task/join, Share Extension и возврата после авторизации.

Не подменять обработчики существующих destinations заглушками. Не открывать по нажатию меню новый чат и не записывать демонстрационный контент в пользовательское хранилище.

## 5. Связка «Карта / Слайды / Чат»

### Документ и его презентации — частично отложено

Ввести общую оболочку проекта вокруг карты. На первом этапе проект может быть логической оболочкой mapID с выбранным deckID и conversationID; не требуется немедленная миграция всех данных в новую сущность Project.

**Текущая реализация:** действие «Слайды» из карты сохраняет вход в создание новой презентации. Показывать параметры и явное действие запуска; само переключение/перерисовка экрана не запускает генерацию. Создание, прогресс, отмена и ошибка сохраняют карту и введённые параметры. Повторный тап по работающей операции не создаёт вторую генерацию. Уже сохранённые презентации открываются через существующую библиотеку.

**На потом:** поиск по sourceMapID при входе, автоматическое открытие последней презентации, состояния 0/1/несколько, переключатель вариантов и «Создать ещё». Макеты `slides-versions/` и `project-continuity/02-slides-switcher.png` — резерв, а не задание текущей итерации.

Слайды из темы без карты остаются самостоятельными, без фиктивной карты. Удаление карты не должно автоматически удалять сохранённые презентации. Сохранить существующие связи источников; откладывается новый способ входа и переключения, а не сохранение документов.

Для презентации из ветки хранить sourceNodeID вместе с mapID и базовой версией; при удалённой ветке сообщить, что источник недоступен, предложить выбрать другой. Не заменять его корнем автоматически.

### Обновление из карты

sourceMapID недостаточно для уведомления «Карта изменилась». Хранить fingerprint или revision содержимого источника, использованного при создании/последнем принятом обновлении. Изменение zoom, сворачивания, pin или личного фокуса не делает слайды устаревшими. Ручное изменение слайда не делает исходную карту изменённой.

Кнопка «Обновить из карты» сначала создаёт предложение. Пользователь видит, какие слайды изменятся; можно сохранить результат отдельной презентацией. Первый безопасный вариант обновления — копия, если точное сопоставление веток и слайдов ещё не поддерживается. Нельзя обещать точечный diff без стабильной привязки элементов к источнику.

Применение сохраняет ручные правки вне выбранной области; исходное состояние остаётся доступным через Undo/снимок. Если текущая ревизия изменилась за время генерации, предложение не применяется вслепую: пересчитать или предложить копию. Актуальные ссылки и права проверить непосредственно перед применением.

### Чат проекта

Использовать устойчивую историю, связанную с mapID/проектом, а не локальный @State NodeChatView. Расширения Codable должны читать старые данные и не теряться в sync/экспорте. Не делать отдельный разговор на каждый тап вкладки. Чат проекта по умолчанию личный: совместный доступ к карте не публикует историю разговора другим участникам.

Контекст виден над вводом: карта; опционально выбранная ветка; опционально презентация и slideID. Привязывать по ID, а не по номеру слайда. Пользователь может снять локальный контекст. При удалении узла/слайда показать изменение контекста и не отправлять следующий запрос о другом элементе молча.

Обычный вопрос получает ответ. Команда на изменение даёт просмотр результата, целевую область и действие применения; затем доступна отмена. Простые прямые ручные действия не требуют дополнительного подтверждения. Ответ, сгенерированный на устаревшем документе, проверяется на конфликт до записи.

Сохранить draft и историю при переключении вкладок и после перезапуска. Явно определить локальное хранение/синхронизацию чата; не обещать перенос между устройствами до реализации. Общий помощник продолжает работать со своим контекстом и разрешением доступа к картам; переключение в проект не стирает его разговор.

## 6. Довести карту без потери текущих возможностей

Сделать соответствующие новым инспекторам входы ко всем существующим действиям: создание/переименование узла, сосед/ребёнок, заметка/ссылка/фото/AI-изображение, задачи/срок/приоритет/emoji, callout, рамка, дополнительная связь, перенос и порядок веток, сворачивание, фокус, поиск, zoom/fit, стили, Undo, экспорт, совместный доступ, история, учёба и показ карты.

Проверить жесты: выбор не панорамирует карту, панорамирование не перетаскивает узел, pinch не вызывает контекстное меню. При открытой панели выбранный узел остаётся видимым; при закрытии не сбрасывать масштаб. Поддержать длинный русский текст, emoji, крупные изображения, несколько сотен узлов и работу без сети с локальным документом.

Форма и метки независимы. Темы задают значения по умолчанию, локальный стиль переопределяет их. Массовое применение к ветке и сброс локального оформления явно показывают область и поддерживают отмену. Пользовательские метки/пресеты сначала добавить в модель, хранение и поиск; не рисовать рабочие контролы над отсутствующей функцией.

Viewer общей карты может читать заметки/фото, искать, менять личный zoom/сворачивание. Редактирование данных и AI-применение закрыты также на уровне операции, не только скрыты кнопки. Доступ может быть отозван во время открытого экрана. Публичная ссылка-снимок и приглашение в совместное редактирование — разные действия с разными пояснениями.

История: список → просмотр → восстановление с сохранением текущего состояния и подтверждением. Учёба: источник всей карты/ветки, пустая колода, вопрос/ответ, оценка, итог, AI-ошибка/повтор/лимит. Today: просрочено/сегодня/выполнено/пусто; нажатие ведёт к тому же nodeID в карте.

## 7. Довести презентации

Объединить пользовательский опыт встроенных полей макета и свободных элементов. Нажатие выбирает, повторное нажатие/«Изменить текст» редактирует. Текст сохраняет семантическую связь с title/bullets/таблицей для AI и экспорта; не превращать все слайды в плоские картинки. Resize текстового блока и размер шрифта — разные действия. Для маленького телефона предусмотреть увеличенный холст, возврат к fit и доступ к панели при клавиатуре.

Смена макета сохраняет исходное содержимое. Переполнение показывать, предложить разделить на слайды; не брать молча первые пять пунктов и не выдавать условное «100%» за факт. Смена темы не меняет текст, числа и порядок. Сохранение стиля и шаблона — разные операции.

Довести инспекторы текста, фото (замена/кадрирование/ошибка), фигур и слоёв, таблиц и диаграмм (ввод значений, подписи, отсутствующие данные). Слои, перемещение, resize и поворот имеют понятные границы холста и отмену. Колонтитул/логотип бренда, фон, анимация появления и переходы не должны теряться при редизайне.

Сетка слайдов: drag-to-reorder + доступные команды перемещения, стабильные IDs, дублирование с новыми IDs всех вложенных элементов, удаление с Undo. Определить последний слайд: вместо неработающего Delete показать объяснение или безопасно оставить один пустой слайд. Скрытие требует модели и единого правила: пропускается при показе, экспорт по умолчанию исключает, в экспорте можно включить явно.

«Этот слайд / Вся презентация» требует реального переопределения стиля слайда; экспорт и превью используют ту же иерархию. До завершения поддержки не показывать полный набор настроек как якобы действующий только на текущий слайд.

Показ: полный экран и докладчик, текущий/следующий слайд, заметки, таймер, выход без потери позиции, внешний экран если поддерживается. Не путать показ веток карты с показом презентации.

Экспорт: реальные PNG/PDF/OPML/Markdown карты и PPTX/PDF презентации, прогресс, повтор после ошибки и системное меню сохранения. Проверить реальные файлы, включая русский текст, изображения, таблицы, диаграммы, длинные заголовки и пользовательские стили. Существующий DeckExportTests проверяет конкретный длинный заголовок; это не полная гарантия соответствия новых дизайнов.

## 8. Состояния и доступность

Для каждого асинхронного действия определить: idle, working, success, failure, cancelled. Отдельно: нет сети, лимит, нет подписки, не выполнен вход, отказ доступа к файлу/микрофону/фото, документ удалён, потеря права редактирования. Сохранить пользовательский ввод после отказа; после sign-in/paywall вернуться к исходному действию и не выполнять его дважды.

Различать «Сохранено на устройстве», «Синхронизация», «Нет сети» и ошибку записи. Не показывать успех лишь по изменению @Published-массива. Поддержать EN/RU и шесть существующих тем оболочки. Проверить Dynamic Type, VoiceOver, Reduce Motion, safe areas, клавиатуру и три размера iPhone. Не использовать цвет как единственный индикатор задачи/приоритета/ошибки.

Новые настройки должны сохранить восстановление покупок, управление подпиской, удаление аккаунта, выход с проверкой несинхронизированных данных, согласие ИИ, доступ помощника, календарь/уведомления, язык/темы и поддержку. Не добавлять API Keys. Не менять цены и тарифные ограничения в рамках редизайна.

## 9. Этапы реализации

1. Новый Menu, маршруты и анимация; сохранить все старые назначения и переходы. Проверить возврат и прерывание.
2. Общая оболочка проекта, постоянная история чата, безопасное обновление из карты. Автоматическое открытие и переключение сохранённых презентаций из карты отложены.
3. Перенос существующих функций в новые редакторы и полное покрытие состояний; устранение расхождений макетов и моделей.
4. Дополнительные метки/пресеты и индивидуальные стили слайда с совместимым хранением и экспортом.

Не выполнять необратимые миграции и не удалять пользовательские данные ради нового интерфейса. Не публиковать билд и не менять App Store материалы в этой задаче. Не использовать симулятор с реальным аккаунтом пользователя; для проверки создать/выбрать отдельный тестовый и работать с demo-данными.

## 10. Приёмка

- Главная после сплеша — помощник; кнопка снизу называется «Меню»/Menu.
- 10 быстрых открытий/закрытий меню, разворот анимации и background/foreground не дают двойного слоя, невидимой блокировки или потери draft.
- Меню → новая карта/презентация/Today/библиотека/шаблоны/настройки → назад сохраняет правильный маршрут.
- Сеть не нужна для открытия меню и локальной библиотеки; обновление recent не проигрывает каскад повторно.
- Reduce Motion и VoiceOver имеют отдельную проверку; устройства с кнопкой Home не перекрывают нижнее действие.
- «Слайды» из карты сохраняют явный сценарий создания без автоматической генерации при открытии; готовые документы доступны в библиотеке. Проверены удалённая карта/ветка и standalone deck. Новый переключатель вариантов не входит в приёмку.
- Повторное открытие чата проекта и перезапуск приложения восстанавливают историю/черновик; история общего помощника не смешивается с ней.
- Переключение вкладок не сбрасывает выбранный slideID/nodeID, zoom и несохранённый ввод.
- AI-ответ по старой ревизии не перезаписывает новые ручные/совместные правки; отмена возвращает ожидаемое состояние.
- Смена макета не придумывает числа и не теряет неразмещённый текст; тестировать длинный список, таблицу, цитату, диаграмму и возврат к предыдущему макету.
- Viewer не меняет карту через панель, жест, чат или отложенный AI-ответ.
- Тариф/авторизация/согласие не теряют выбранный источник и не запускают двойную генерацию.
- Экспортированные файлы открываются и визуально проверены; новые поля корректно читаются из старых и новых документов.
- Build и релевантные существующие тесты проходят. Для новых рисков добавить проверки persistence, сохранения документов и связей источников, конвертации макетов, конфликтов и маршрутов, а не тесты декоративных констант.
- В финальном отчёте показать что реализовано, что проверено на устройстве/симуляторе, оставшиеся ограничения и реальные скриншоты/запись перехода. Не отмечать сценарий готовым только по существованию обработчика или PNG.
